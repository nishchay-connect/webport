Some engineering questions begin as technical puzzles: *Can we build this?* Others are harder: *What would making it useful require?*

The second question brings a different set of constraints into the room. People, context, failure modes, maintenance, access, and trust stop being peripheral details. They become part of the system.

## Questions to investigate

- What is the smallest experiment that could challenge the core assumption?
- What changes when a prototype leaves a controlled setting?
- Where should a machine stop and a person take over?
- What would disconfirm the original idea?

## A possible direction

A strong project journal could follow these questions from initial intuition to implementation and revision, preserving the tradeoffs that a polished project summary usually hides.
